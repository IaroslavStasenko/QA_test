# Тест-план: Электронная ведомость оценок в школе

**Версия документа:** 1.0  
**Статус:** Черновик  
**Тип тестирования:** Ручное функциональное и нефункциональное тестирование

## 1. Цель тестирования

Проверить, что электронная ведомость оценок позволяет учителям корректно выставлять и изменять оценки, ученикам и родителям — просматривать результаты обучения.

Основная цель — убедиться в корректности выставления оценок, сохранности данных, разграничении прав доступа и удобстве использования системы.

## 2. Объект тестирования

Веб-приложение «Электронная ведомость оценок», предназначенное для учёта успеваемости учеников школы.

### Основные модули системы

- Авторизация системы.
- Управление пользователями и ролями.
- Список классов и учеников.
- Список учебных предметов.
- Просмотр электронной ведомости.
- Добавление и редактирование оценок.

## 3. Область тестирования

**Авторизация**
- Вход с корректным логином и паролем.
- Обработка неправильного пароля.
- Проверка обязательных полей.
- Выход из системы.
- Ограничение доступа к страницам после выхода.

**Роли и права доступа**
- Учитель может выставлять оценки только в рамках разрешённых ему предметов и классов.
- Ученик может просматривать только собственные оценки.

**Работа с оценками**
- Добавление оценки ученику.
- Редактирование существующей оценки.
- Проверка допустимого диапазона оценок.
- Сохранение оценки после обновления страницы.
- Отображение оценки в соответствующей строке и столбце ведомости.

## 4. Тестовое окружение

- **Тип приложения:** веб-приложение.
- **Операционная система:** Windows 10/11.
- **Браузер:** Google Chrome.
- **Тестовые данные:** вымышленные ученики, классы, предметы и оценки.
- **Доступы:** тестовые аккаунты администратора, учителя, ученика и родителя.

## 5. Тестовые данные

Для проверки использовать следующие условные данные:

| Параметр | Пример |
|---|---|
| Класс | 7А |
| Ученик | Иванов Иван |
| Предмет | Математика |
| Учитель | Петров Пётр |
| Оценки | 3, 4, 5 |
| Учётная запись | Тестовый пользователь |

## 6. Критерии завершения тестирования

Тестирование считается завершённым, если:

- Выполнены все запланированные тест-кейсы либо зафиксированы причины их невыполнения.
- Все найденные дефекты зарегистрированы.
- Проверены основные пользовательские сценарии.
- Критические дефекты отсутствуют либо их статус и влияние согласованы с ответственными лицами.
- Подготовлен итоговый отчёт о тестировании.

## 7. Ожидаемые результаты

По завершении тестирования должны быть подготовлены:

- Набор тест-кейсов.
- Чек-лист основных проверок.
- Отчёты об обнаруженных дефектах.
- Итоговый отчёт о результатах тестирования.
